2026.08.05P03 · ML 范式

机器学习基本范式

核心问题：模型根据什么信息做出预测？

三种学习范式 ★

  • 监督：有标签 X→Y（分类/回归）
  • 无监督：无标签找结构（聚类/降维）
  • 强化：有奖励学策略
  • 自监督：从数据自身造标签（MLM）

核心目标 ★

在训练集学规律，能泛化到未知数据。

偏差—方差

偏差太简单→欠拟合；方差太复杂→过拟合；噪声是误差下限。

评估指标

分类：Acc/P/R/F1/AUC | 回归：MAE/MSE/RMSE/R²

2026.08.05P05 · 梯度下降

梯度下降

一句话定义
沿损失下降最快的方向更新参数。
核心公式 ★
θ ← θ − η · ∇L(θ)

θ参数 · η学习率 · ∇L(θ)损失对参数的梯度

为什么这样设计

梯度指向上升最快方向 → 沿负梯度走下降最快。

我的直觉

像蒙眼下山——坡度是梯度，步长是学习率，谷底是最优解。

三种变体
  • BGD 全量稳但慢 · SGD 单样本快但抖 · Mini-batch 工程默认

! 梯度指向上升，要减别记成加。

# Karpathy/micrograd · engine.py（节选）
class Value:
    def __init__(self, data, _children=(), _op=''):
        self.data = data; self.grad = 0
        self._backward = lambda: None
        self._prev = set(_children); self._op = _op

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), '+')
        def _backward():
            self.grad += 1.0 * out.grad
            other.grad += 1.0 * out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), '*')
        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward
        return out

    def backward(self):  # 拓扑排序 + 反向传播
        topo, visited = [], set()
        def build(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev: build(child)
                topo.append(v)
        build(self)
        self.grad = 1.0
        for node in reversed(topo): node._backward()

2026.08.05P07 · Transformer

Transformer 结构

用 Self-Attention 替代 RNN：全并行、长程依赖好。
核心公式 ★
Attention(Q,K,V) = softmax(QKᵀ/√dₖ)·V
  • Q查询 / K键 / V值
  • √dₖ：防点积过大导致 softmax 饱和
  • Multi-Head：多头并行再拼接
结构图
token→[Embed+位置编码]
        ↓
 ┌ Multi-Head Attention ┐
 │  Add & LayerNorm      │ ×N
 └ Feed-Forward (MLP) ──┘
        ↓
   Logits→softmax
为什么这样设计

RNN 必须逐步算无法并行；Attention 让每个位置直接看所有位置。

2026.08.05P09 · 强化学习入门

强化学习入门

先抓交互闭环：状态→动作→奖励→新状态。
四个核心对象 ★
  • Agent：做决策的主体
  • Environment：环境
  • State：当前状态
  • Action / Reward：动作与回报
核心概念

Policy π：策略，状态到动作的映射
Value V：从某状态出发的期望回报
Return G：累积折扣奖励

学习路线 →

MDP → Bellman → Q-Learning → DQN → Policy Gradient → Actor-Critic → PPO → RLHF

每个算法回答四问 ★
  • 学什么？用什么更新？on/off-policy？解决了什么？

# CleanRL · ppo.py 核心训练循环（节选）
for update in range(num_updates):
    # 1. 收集 rollout
    for step in range(num_steps):
        action, logprob, _, value = agent.get_action_and_value(next_obs)
        next_obs, reward, done, info = envs.step(action)
        # 存入 buffer ...

    # 2. 算 GAE 优势
    with torch.no_grad():
        next_value = agent.get_value(next_obs)
        advantages = torch.zeros_like(rewards)
        lastgaelam = 0
        for t in reversed(range(num_steps)):
            nextnonterminal = 1.0 - nextdone[t]
            delta = rewards[t] + gamma * nextvalue * nextnonterminal - values[t]
            advantages[t] = lastgaelam = delta + gamma * 0.95 * lastgaelam * nextnonterminal
            nextvalue = values[t]
        returns = advantages + values

    # 3. PPO 更新（带 clip）
    for epoch in range(num_epochs):
        for mb in minibatches:
            _, newlogprob, entropy, newvalue = agent.get_action_and_value(mb.obs, mb.actions)
            logratio = newlogprob - mb.logprobs
            ratio = logratio.exp()
            # clip 是 PPO 的核心：限制策略变化幅度
            mb_advantages = mb.advantages - mb.advantages.mean()
            pg_loss = -(mb_advantages * torch.clamp(ratio, 1-0.2, 1+0.2)).mean()

固定七项，不抄摘要。

1. 解决什么问题 ★

序列建模依赖 RNN，导致无法并行、长程依赖弱。

2. 以前方法为什么不够

  • 长序列梯度消失
3. 核心假设
仅靠注意力（不靠循环/卷积）就能建模序列依赖。
4. 真正的新东西
  • Scaled Dot-Product Attention
  • Multi-Head + 位置编码
